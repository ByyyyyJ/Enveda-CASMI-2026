## 0. 结论

1. **原方案的根本问题是起点**：它按"从零自建"设计，但公开生态已经有一条 0.465–0.468 的完整 pipeline，公榜第一是 0.510。距截止还有 49 天，仓库里还没有任何建模代码。从零按 M1–M5 推进，最好的结果也只是追平公开 notebook。
2. **几处优先级判断被公开消融证伪**：正向模拟（ICEBERG / GLACIER）被原方案排在最低优先级，实际上它是公开 pipeline 涨分的主要来源之一；CLIP 双塔和 de novo 被排得过高。
3. **验证设计的方向是对的，而且是我们唯一的差异化优势**：公开生态基本在用约 125 个分子的公榜调参。但验证设计有三处需要修正（§3）。
4. **修订后的路线**：以公开 pipeline 为基线，先搭一套无泄漏的本地复刻和验证；用误差分解决定改哪里；只投入"新证据"和"新候选来源"，不调权重。

## 1. 原方案没有考虑的新事实

### 1.1 排行榜与公开 pipeline

| 项目 | 数值 |
| --- | --- |
| 公榜第一（2026-10-26） | 0.510 |
| 公榜前 20 | 0.474–0.510，非常密集 |
| 最好的公开 notebook | 0.468（全部是同一条 pipeline 的 fork） |
| 公榜规模（社区估计，官方未公布） | 约 125 个分子，一个分子约等于 0.008 MRR |

公开 pipeline 的结构（V465 / E006 系列，代码 Apache-2.0）：

- **Engine 1**：训练集结构 + COCONUT 共约 71 万个结构，按 10 ppm 质量窗口检索；FPNet 指纹预测 + 4 个 LightGBM 排序器；另有"修饰谱图类似物"的候选生成器。
- **Engine 2**：COCONUT、ChEBI / LIPID MAPS、PubChemLite、训练集结构；证据包括谱库匹配（含 adduct 平移匹配）、类似物传播、指纹模型、MetFrag-lite 碎片匹配；两个 GBM 排序器融合。
- **PubChem 通道**：在 1.06 亿个 PubChem 结构上打分，加文献热度先验，打分公式为 `z(指纹分) + 0.15 × (log(1+物质数) + log(1+PubMed 数))`。
- **融合**：按官方 metric 的身份（互变异构规范化后的 inchikey14）去重，再做 reciprocal-rank 融合。
- **同分子式重排**：前 40 名内按 GLACIER / ICEBERG 的预测谱相似度重排，两者都没有分数时用 MetFrag-lite。
- **神经对比打分器**（`sanpier/casmi-spectrum-model-v1`）：只用于重排第 2–25 名。

### 1.2 公开消融：分数从哪里来

| 步骤 | 公榜增量 |
| --- | --- |
| 0.384 → 0.440（第二引擎 + 热度先验 + 身份融合 + 安全尾部 + window 40，多项同时加入） | +0.056 |
| ICEBERG 同分子式重排 | +0.004 |
| GLACIER（两个版本） | +0.011 |
| ChEBI / LIPID MAPS 候选 | +0.005 |
| PubChemLite 候选 | +0.004 |
| PubChem 热度权重、N1A 等调参 | +0.000 ~ +0.001 |

消融作者的结论是：大的涨分来自**新证据**（模拟器、第二引擎）和**新候选来源**，调权重的收益在噪声范围内。原因是大部分错误答案与正确答案分子式相同，必须靠碎裂信息区分异构体。

### 1.3 化学空间偏移有了定量数据

`casmi26-fold-safe-fpnet` 的说明中给出了 FPNet 的 Top-1 准确率：

| 测试分子 | Top-1 |
| --- | --- |
| 训练过的分子 | 97% |
| 训练集内、按 identity 留出的分子 | 68% |
| 从未见过的 250 个天然产物（enveda-np-examples） | **33%** |

这是原方案 §3 "两维偏移"假设的直接证据：在没见过的天然产物上，指纹模型的 Top-1 从 68% 跌到 33%。**化学空间偏移是当前最大的瓶颈**。

### 1.4 合规信息更新

- 主办方澄清（discussion 745072）：`train.parquet` 视为开源；只因使用 `train.parquet` 而带有非商业限制的数据集可以使用。
- 公开 pipeline 的 ICEBERG / GLACIER 权重来自 **MassSpecGym checkpoint**（ms-pred，MIT），不是 NIST。原方案 §7.6 担心的 NIST 合理性问题不适用。
- 公开数据集的许可五花八门：CC BY-NC-SA 4.0、"Other"、"Unknown"，例如 `casmi-spectrum-model-v1` 的许可是 Unknown。最终提交前需要逐个审计（§5 W6）。

## 2. 逐条反驳

### 2.1 战略层

#### ① 从零自建（§5、§8、§11）

原方案把模块 1–8 全部自建，M2 才首次提交，而且首次提交只是纯谱库检索。现在已有现成的 0.468 基线，这样排期等于前 4–5 周都在重造别人已经公开的部分。

修正：第 1 周就复现公开 0.468 notebook，作为排行榜锚点；自建工作只放在能产生新证据的地方。

#### ② 用排行榜反推类别占比（§4.4）

公榜约 125 个分子，单次提交 MRR 的标准误约为 √(0.2/125) ≈ 0.04，95% 区间约 ±0.08。再加上类别 1 在验证集上的 MRR 本身有偏（enveda-np-examples 偏容易），这个反推没有可用精度。

修正：放弃反推，改为**对类别配比做敏感性分析**。在 1:1:1、2:2:1、1:2:2 等几种配比下比较方案，选在各种配比下都不差的方案。

#### ③ 对排行榜的使用（§9.8）

原方案说"小于约 0.01 的变化视为噪声"，这个判断过于乐观。同一批分子上两次提交的**配对差**噪声确实小一些（只有排名变动的分子贡献差异），但公榜分数到私榜分数的泛化误差是 ±0.04 量级。公榜 0.47–0.51 的头部差距很可能有相当部分是在 125 个分子上过拟合。

修正：两个最终提交一个以公榜为锚（公开基线 + 已验证的改进），一个以本地验证最优为准，用来对冲私榜洗牌。

### 2.2 优先级判断

#### ④ 正向模拟被严重低估（§5 的 5c、§7.6、§8.1 的 P3）

原方案把 5c 列为"可选，M5 视余力决定"，理由是"MARASON 训练需要两张 24GB GPU"。但：

- 不需要自训：MassSpecGym checkpoint 的 ICEBERG / GLACIER 已经打包好，可以在 Kaggle T4 上离线运行；
- 消融显示它是公开 pipeline 涨分的主要来源（+0.015）；
- 它正好解决原方案 §9.1 自己识别出的核心难点：同分子式异构体排序。

修正：升为 P1 主线（基线中已有，P0 是复现它）。改进方向不是"接入"，而是提高**覆盖率**。目前 GLACIER 以 `[M+H]+` 谱打分，没有 `[M+H]+` 谱的分子要把 `[M+NH4]+`、`[M-H2O+H]+` 换算成 `[M+H]+` 代理（N1A）。MassSpecGym 只有正离子数据，所以负离子谱很可能没有正向模拟证据（待在代码中核实）。enveda-np-examples 中负离子谱约占 33%。

#### ⑤ CLIP 双塔作为 P1 主线（§7.3、§8.1）

公开 pipeline 已经有神经对比打分器，加入后只带来约 +0.001 ~ +0.003，而且只用于第 2–25 名。再训练一个 DreaMS + ECFP 双塔，大概率只是同类信号的又一份拷贝。

原方案的设计（难负例、multi-positive、元数据 token）本身没有问题，问题在于目标。真正的瓶颈是 §1.3 的化学空间偏移：在天然产物上 Top-1 只有 33%。

修正：模型训练的目标改为"**天然产物域适配**"，而不是"再做一个检索塔"。具体做法：

- 按 NP-likeness 或 COCONUT 收录给训练样本加权；
- 用 enveda-np-examples 做早停；
- 按天然产物骨架做难负例。

架构可以沿用 FPNet（直接替换公开 pipeline 里的组件，收益可以单独测量），也可以用 DreaMS 双塔，由本地验证决定。

#### ⑥ de novo 生成（§7.5、5d）

MS-GPT / FRIGID 依赖分子式（只能用预测值）、只支持正离子、依赖有 batching bug 的 MIST 编码器，在已知分子式时 Top-1 也只有约 20–30%。用在天然产物、未知分子式、混合极性的场景，预期 MRR 接近 0，而接入成本很高。

修正：类别 3 改用**类似物枚举**。官方描述的类别 3 是"假设的天然产物、天然产物类似物"，它们通常与已知结构只差一步修饰。做法：

1. 对谱库近邻（高 modified cosine 的已知结构），由前体质量差推断修饰（+O、+CH2、±H2O、+己糖、+丙二酰等）；
2. 用 RDKit 反应 SMARTS 在所有可行位点上枚举产物；
3. 按质量过滤，用正向模拟和指纹模型打分。

Top-25 可以容纳一个修饰的全部位置异构体，按 MRR 计算，即使排不到第一也有可观的分数。公开 pipeline 已经有一个类似物生成器，第一步是测量它的召回率，再决定是改进它还是重写。

#### ⑦ 候选先验的符号依赖类别（§6.4、§4.3）

"在训练集中有谱"这个先验对不同类别方向相反：

- 对类别 1 是正信号；
- 对类别 2 / 3 的分子，正确答案按定义**没有**公开谱。如果一个候选在训练集中有谱、而查询谱和它的参考谱不像，这其实是**反证**。

原方案 §4.3 计划只用补充验证集 B（V-pub-nps / novel）训练 LightGBM，那里正确答案全都不在训练谱库中，ranker 会学到"有谱 = 负信号"，在类别 1 上出错。

修正：

- ranker 的训练行要混合三种模拟类别；
- 显式加入"**缺席证据**"特征：候选在参考库中有谱时，它与查询谱的最高相似度。"有谱但不像"是最有用的组合；
- 在 §2.1 ② 的多种配比下检查 ranker 是否稳健。

#### ⑧ 热度先验的验证偏差（§6.4）

enveda-np-examples 是刻意挑选的常见天然产物，文献热度很高，会**高估**热度先验的价值。而类别 2 的定义是"没有公开谱"，这类分子研究得通常较少，热度先验对它们偏弱。

修正：按 PubMed 文献数把验证分子分层，单独报告冷门分子上的结果。公开的 `casmi26-pubchem-popularity-prior` 可以直接提供分层依据。

### 2.3 验证设计（§4）

#### ⑨ V-np-novel 删除 Tanimoto ≥ 0.7 的近邻，过于悲观

类别 3 的定义只是"不在 PubChem 中"，没有说没有近邻。天然产物类似物恰恰大多有高相似度的已知近邻。删掉近邻后，类似物枚举这条最有希望的路线在验证集上会被人为判死。

修正：

- 主设置只删除精确结构（inchikey14，含互变异构）；
- Tanimoto ≥ 0.7 的版本保留为压力测试，单独报告。

#### ⑩ 预训练组件的泄漏比原方案估计的严重

公开 pipeline 的 FPNet（`fpnet-full1`）是用包括 enveda-np-examples 在内的全部训练数据训练的，在见过的分子上 Top-1 高达 97%。直接拿公开 pipeline 在 V-np-* 上评估，结果没有意义。

修正：本地复刻必须使用 fold-safe 组件。

- `casmi26-fold-safe-fpnet` 已提供 5 折和排除了 250 个天然产物的 FPNet；
- LightGBM ranker、Engine 2 的指纹模型、神经打分器需要逐个确认训练数据，必要时按折重训。

这是修订方案中工作量最大的一项，也是我们相对公开生态的核心优势。

**实测（2026-10-26）**：ICEBERG / GLACIER 的 checkpoint（`msg_all`）在 MassSpecGym 上训练。按官方 metric identity 比对，enveda-np-examples 的 250 个结构中有 **236 个（94%）** 在 MassSpecGym 里；riken 68%、mona 74%、gnps 43%，enveda-180 几乎为 0（26 / 182,941）。因此：

- 本地验证无法如实评估这两个模拟器，在 V-np-* 上它们的贡献会被严重高估；
- 评估其他组件的改进时，要同时报告"去掉模拟器"的版本，避免把模拟器的泄漏分数算进改进里；
- 模拟器本身的改动（如扩展 adduct 覆盖）只能靠排行榜的配对比较来判断，或者在排除验证分子后重训 ICEBERG（成本待估）。

社区的 5 折已核实（`scripts/verify_folds.py`）：按当前官方 metric（先去立体化学）重算后，identity 与建折时完全一致，没有跨折的分子，覆盖全部训练结构；250 个天然产物分布在 5 个折中（55 / 51 / 52 / 47 / 45）。

#### ⑪ 250 个分子的统计功效

MRR 在 250 个分子上的标准误约为 0.03。即使用配对 bootstrap，也只能可靠分辨大约 0.02–0.03 以上的差异。

修正：主验证集用于定方向；补充验证集 B（公共库天然产物，上千个分子）用于分辨细小的差异。

### 2.4 规则与定义

#### ⑫ 类别定义存在重叠

官方原文：类别 2 是"in PubChem **or** COCONUT"，类别 3 是"not in PubChem at all"。一个在 COCONUT 中、不在 PubChem 中、也没有公开谱的结构，同时满足两条定义。

含义：COCONUT 中不在 PubChem 的那部分结构，可能是类别 3 的答案来源。应把这部分单独作为一个候选层和融合特征。可在讨论区向主办方确认。

#### ⑬ 碎片同位素估计碳数（§9.6）

MS2 中碎片的同位素比例取决于四极杆隔离窗口截取了多少前体同位素，与碎片本身的元素组成没有简单关系，用来估计碳数不可靠。建议删除这一项。

### 2.5 原方案中仍然成立的部分

- 两维偏移的分析（§3.1），现在有了定量支持（§1.3）；
- 三种留出方式对应三类新颖度（§4.2），只需按 ⑨ 修正；
- 与官方 metric 一致的规范化与去重（§9.10），公开 pipeline 也是这么做的，并且证明了这样做有收益；
- 许可证收录标准（§6.2）；
- bootstrap 置信区间、捷径检查、泄漏单独报告（§9.8）。

```text

        │
        └─ 替换为 fold-safe 组件 ──► 本地无泄漏复刻

                                        ▼
                    验证集 V-np-lib / nps / novel（精确删除）+ V-pub
```

### 3.4 已定决策（2026-10-26，单人开发）

1. **以公开 pipeline 为基线**。理由：一个人做、只剩 7 周，自建在截止前追不上 0.468。公开代码是 Apache-2.0，符合规则；附带的数据集和权重需要在 W6 逐个审计许可。我们自己的工作集中在本地验证、误差分解和 1–2 个新证据模块上。
2. **采用社区的 identity-disjoint 折作为底层划分**，并在上面叠加我们的三种留出方式。fold-safe FPNet 只对它自己的折有效，另起划分就要全部重训。它的 5 个模型都排除了 enveda-np-examples 的 250 个分子，所以 V-np-* 在 FPNet 上天然无泄漏。W1 需要核实三件事：
   - 折的 identity 定义是否与官方 metric 一致（互变异构规范化后的 inchikey14）；
   - 折文件是否覆盖全部训练分子；
   - pipeline 中其他学习组件（LightGBM ranker、Engine 2 指纹模型、神经打分器）是否见过 enveda-np-examples。

   见过的组件，按影响大小决定重训或在验证时替换掉，不追求全部重训。
3. **不再有队友分工**。P1 只做误差分解指出的最大一两项。
